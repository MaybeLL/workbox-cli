# Workbox 第二阶段实施方案

状态：本阶段已在工作区实现。以下保留经确认的设计与验收范围。产品约束见[设计决策](Decisions.md)，代码起点见[实现导览](Implementation.md)。

## 本次开发的设计与清理要求

按《软件设计的哲学》的深模块原则，从调用方要完成的操作设计接口。接口要说清输入、结果、失败时留下的状态；将必须配合使用的步骤和容易遗漏的不变量放进同一处实现。以下三处用来检验设计：

| 调用方的意图 | 模块承担的复杂性 | 从接口验收 |
| --- | --- | --- |
| 用一次配置快照准备并发布实例 | 暂存目录的所有权、逐项准备、取消与清理、排他发布。CLI 只提交创建请求并呈现结果。 | 从创建入口注入一项下载失败：能定位失败项，目标路径仍可用原命令重试。并发创建只能有一个发布者。 |
| 读取指定版本的 GitLab 文件、检索一个项目 | 主机与凭据匹配、版本定位、分页和覆盖状态。文档下载与源码读取复用同一套按 SHA 取文件的逻辑；同次创建的分支快照由创建操作持有。 | 两个调用方都能取得相同 SHA 的原文；第二页失败时，搜索调用方拿到已有命中和不完整原因。 |
| 将一项已登记的 Skill 准备到实例暂存区 | Git 与 npx 各自取来源、验证实际名称和安装范围。创建流程只消费准备结果，登记和导入仍可独立执行。 | 两类来源经过相同的实例安装契约验收；全局 Skill 的收据与卸载规则仍由现有全局安装流程负责。 |

复用现有 `configStore` 隔离 SQLite/MySQL 的事务和迁移细节。接口可以是普通 Go 函数或具体类型的方法；有实际变化点再引入 Go interface。审查时看调用方还需要记住哪些顺序、知道哪些来源或平台细节。若去掉一层后只少了一次转调，直接合并该层。

每批改动同步清理该流程中已经退出使用的逻辑。例如团队文档和全局 Skill 接手后，删除默认根 `AGENTS.md` 模板、无条件写入分支及失效的测试断言；先将仍在使用的文件写入保护迁到实际调用方。删除前核对生产调用、CLI 与脚本入口、旧数据读写和兼容测试。仍有用户契约的旧命令别名、包格式和数据库迁移路径继续维护。

每批在变更说明里列出本次替代了什么、删掉了什么，以及保留旧路径的具体调用方或兼容依据。验收以入口行为和失败场景为准；旧测试中的有效保护随新入口继续覆盖。

## 0. 配置存储与兼容基础

- SQLite 和 MySQL 同步升级，共用 configStore 的快照与原子提交契约。为现有 Workbox 配置增加可选文档、Skill 引用，新增 Skill 注册实体；采用数据库 schema 4；SQLite 事务迁移，MySQL 在现有 schema 锁内允许中断恢复，最后写版本。旧库只读按空值解释，下一次写入按现有迁移机制升级。把字段贯穿 show/list、复制后端、导入导出；配置包保留现有 JSON 字段。读旧包按空项处理，含新增字段的包用 v2；无新增内容仍可导出 v1，旧客户端应清晰拒绝不支持的包。
- 先落地两个新增集合的快照、严格编解码、适配器和包格式，再开放配置入口。SQLite/MySQL 读 schema 1–3 时缺失集合按空处理；新增字段由 schema 4 写入。测试旧版本读取、写时迁移、MySQL 中断重试、新旧包往返、严格旧客户端拒绝 v2。保留现有命令别名与 JSON 键。
- 新增 Skill 时，检查所选仓库 target_dir 与实例 Skill 目录的冲突。旧配置没有选择 Skill 时，即使历史路径位于 .agents/skills 下，也继续可读可用；仅在该配置增加冲突项时要求修改。文档始终遵守 D-011。

## 1. 团队文档与实例发布

- 扩展 `workbox-config add/update --docs-file FILE`。文件是有序 JSON 数组；每项形如 `{"project_url":"https://gitlab.example.com/team/handbook","ref":{"type":"branch","value":"main"},"source_path":"rules.md","target_path":"AGENTS.md"}`。支持 branch 和完整 commit SHA。省略参数保留旧值，空数组清空。只存来源与目标，文档正文由 GitLab 维护。
- `init` 增加可跳过的 GitLab 实例及隐藏 token 输入；脚本支持 `--gitlab-host` 和 `--gitlab-token-file`；新增 `workbox auth gitlab set --host HOST --token-file FILE` 供初始化后补配或轮换。保留现有 settings.json 的读取契约，个人 GitLab 凭据独立于业务存储切换。按 HTTPS 主机和端口隔离凭据，使用已有的私有目录、文件权限和原子写机制。凭据不进入业务库、导出、日志或实例。文档和代码共用 GitLab API 客户端；跨来源重定向不转发 token。
- GitLab 连接支持单独补配别名，例如 `workbox auth gitlab alias set --ssh-host ssh.company --host gitlab.company:8443` 将 SSH 端点关联到已配置的 HTTPS 实例。别名保存在本机连接配置中，不进入共享配置、实例快照或导出包。按 SSH 主机及端口区分端点，省略端口按 22 处理；修改别名无需重填 token。
- 配置保存和导入共用路径校验，检查大小写折叠、相对路径、祖先重叠、保留目录及 repo 的 target_dir。允许根 AGENTS.md 作为文档；保存冲突返回两项及其路径。`plan` 只读本地快照和目标条件。
- `create` 在目标同一父目录创建私有暂存目录。一次加载配置和引用，按项目、分支解析一次 SHA，通过文件 API 按 SHA 原样取正文。写仓库清单、显式文档、选中 Skill；未配置根文件就不生成，未选 Skill 就不创建 Skill 目录。不检出业务仓库，不执行配置脚本。将全局 Skill 安装已有的 macOS/Linux 排他 rename 提取为接受源名和目标名的发布函数；写完后用同一父目录句柄发布，目录发布不可覆盖竞争者；失败报告具体项与阶段，只清理本次暂存。成功仍返回 prepared 与同一快照中的 init_script。
- **创建的提交点是排他 rename 成功。** 发布前最后检查取消信号，已取消则清理暂存，返回 `INTERRUPTED` 和退出码 130。信号与 rename 并发时，以发布结果决定答复：已经成功发布，CLI 就保留 `ok: true`、`state: prepared` 和退出码 0，外层取消处理不能将它覆写为失败。从 CLI 的 Run 入口分别在发布前、发布后输出前注入取消，核对 JSON、退出码与磁盘；前者用原路径重试成功，后者确认原目标完整。
- 发布此批之前把原内置根指引迁入全局 Skill；既有实例保持原样。升级测试覆盖上一版全局 Skill：内容冲突时沿用备份移开、再次运行 skill install、重新开始会话的流程，保留用户改动。验收覆盖无文档离线创建、分支在两次读取之间移动、缺文件、取消、同目标并发、一条原命令重试。安装冒烟先验证无文档配置未生成根 AGENTS.md，再由测试模拟用户写入该文件，卸载后逐字节比对，保留原有的用户内容保护验收。

## 2. 用户 Skill 与一键迁移配置

- 新增 `skill-config add/list/show/update/remove`，以及 `workbox-config add-skill/remove-skill NAME SKILL`。Git 登记例：`workbox skill-config add --git-url URL [--subdir DIR] [--branch NAME | --commit SHA]`。复用本机 Git 认证，只读取来源确定的 SKILL.md 的 front matter.name；缺省子目录为根、缺省版本跟随远端默认分支。创建时取选中目录全部配套文件、剔除 Git 元数据并复核名称。Git Skill 的源仓库获取和业务仓库 checkout 独立。
- npx 登记例：`workbox skill-config add --installer npx-skills URL --skill grill-me`。只接受这个结构，注册不执行安装器。全局 Skill 把用户提供的原始命令翻译为注册命令。创建时在独立暂存项目中以参数数组非交互运行发布时锁定并通过真实夹具验证的 skills CLI 版本，显式选择项目级、单个 Skill 和目标 Agent。隔离安装器的 HOME、Agent 写入目录与临时文件，测试调用者个人 Skill 目录零写入，仅发布选中的完整 Skill 目录，验证入口和名称。安装器的锁文件和其他 Agent 布局留在暂存区。两类来源均拒绝保留名 workbox、非法名称和路径逃逸。
- 同名同来源幂等，不同来源冲突。显式 update 指定旧登记名并校验新来源仍声明同名；被引用时 remove 列出引用者。实例安装不写全局 Skill 安装收据。
- 保留一键导出全库和一键导入到新库。包中包含全部 Skill 登记及其来源，包括尚未被任何 Workbox 引用的登记；保留初始化脚本正文，排除个人 token、远端文档和 Skill 正文、安装产物及本地 ID。导入对 Skill 离线验证结构、名称与引用；保留已有业务仓库的导入校验。冲突整批失败。导入及后端复制的空包判断、变更计数都纳入 Skill。验收增加只有一个未引用 Skill、其他集合均为空的库：导出 v2，离线导入新库后可按名称查到相同来源，再导入返回已存在。用两套独立配置库验证完整往返，另测多人并发注册、更新与删除，以及 Git/npx 安装失败后原路径重试。

## 3. Workbox 范围内的远程代码读取

- 新增 `workbox search --path DIR --query TERM [--repo NAME ...] [--ref NAME=REF ...]` 和 `workbox read --path DIR --repo NAME --file PATH [--ref REF] [--lines START-END]`。仅这两个可重复选择参数放宽现有解析器的重复标志限制；重复选择同名仓库、重复赋予同一仓库 ref 或 ref 指向选集外均返回参数错误。省略 --repo 搜全部。从实例 .workbox/repos.json 解析仓库名称，拒绝清单外项目；读取凭据不需要业务数据库。全局 Skill 负责向用户一次确认未明确的范围和版本；CLI 非交互，用调用覆盖值、实例 ref 提示、实例默认分支依次选择版本。
- 将来源地址解析为“GitLab 实例 + 完整项目路径”。HTTPS 按主机及 HTTPS 端口确定实例；SSH URL 和 SCP 风格地址先查显式别名，否则匹配同主机名的唯一 HTTPS 实例。去掉 Git 用户名、路径前导斜杠和结尾的 `.git`，保留子组。SSH 端口仅用于识别 SSH 端点。API 请求只向选定的 HTTPS 实例发送其 token，本地检出仍用清单中的原始 URL。
- SSH 端点无法唯一匹配时，错误指出仓库、端点及补配命令；确认实例前不向候选主机发请求。验收同主机三种写法解析为同一项目、同路径在不同实例保持区分、SSH 与 API 异名，以及同主机多个 HTTPS 端口产生歧义。后二者均在原目录补配一次别名后重试，验证第二个仓库可复用映射，清单和共享配置未被改写。
- 搜索按仓库处理分页，返回命中、请求 ref、实际可证实的检索范围、覆盖状态和原因。按后端实际能力支持 branch/tag，固定 SHA 首版只提供文件读取。后端无法证实检索范围时标记覆盖未知，零命中也不能报完整。分页中途失败时保留已取页的命中、标记该仓不完整并继续其他仓库。GitLab 的分支检索不能证明任意 SHA 的完整覆盖。没有可靠的版本证据时报告未覆盖；部分失败通过现有 JSON envelope 返回部分数据和非零退出码。读源码先解析到 SHA，再取原文和所需行，输出仓库、SHA、路径、行号。不得把当前分支索引结果描述为某个固定提交的穷尽搜索。
- 验收覆盖跨 Group、跨主机、逐仓 ref、无权限、分页失败、指定 SHA 不可搜但可读文件。归档一个端到端验收场景：甲导出，乙导入，使用乙自己的凭据创建实例并查询代码；两个账号获得相同配置，各自访问范围如实呈现。

## 交付顺序与验收

按上述依赖顺序拆分可验证变更，最终统一发布。改一项同步更新帮助、全局 Skill、README 和实现导览。每批跑相关测试，合并前跑 Go 全量与 race、SQLite/MySQL 存储契约、macOS/Linux 排他发布和安装冒烟。GitLab API 用测试服务器复现分支变化、分页和认证错误；npx 除替身故障注入外，以固定版本安装器实际验证项目级安装。真实公司 GitLab 的后端覆盖能力单独记录验证结果。

安装器按其[项目级安装接口](https://github.com/vercel-labs/skills#install-a-skill)验证单项选择和输出目录。检索验收按 [GitLab 项目级搜索](https://docs.gitlab.com/api/search/#search-a-project)及[文件读取接口](https://docs.gitlab.com/api/repository_files/)区分候选命中与按 SHA 核实的源码。
