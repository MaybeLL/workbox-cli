## 目标与现状

成员回来继续一个需求时，可以从任意目录执行 `workbox list`，找回**当前用户在这台机器上创建并成功登记的需求目录**。即使切换了团队配置库，或暂时连不上公司网络，也能找到原路径，继续使用原来的分析成果。[产品愿景](../Vision.md)

方案制定时，`plan/create` 共用目标路径预检，已会解析父目录的符号链接。`create` 准备完上下文后排他发布目录，返回 `prepared`。`status --path` 用于检查指定目录中的 Git 检出和 worktree。当时没有本机实例清单。[发布流程](../../internal/workbox/workspace.go) · [实现导览](../Implementation.md)

**已确认的 D-001 条文**

> 当前用户在本机创建的实例按实际绝对路径唯一登记在用户状态目录的独立 instances.db 中。list 跨配置列出记录和当前路径状态，forget 仅移除指定路径的记录。plan 和 create 均检查目标路径占用、已有登记和祖先实例标记，禁止在实例内创建实例。目录发布后即为 prepared，登记失败单独报告。

## 方案与取舍

~~~mermaid
flowchart TD
    P["plan 或 create"] --> C{"目标可用、路径未登记、祖先无实例标记？"}
    C -->|冲突或无法完成检查| E["指出原因和相关路径"]
    C -->|plan 通过| V["返回预览"]
    C -->|create 通过| S["暂存内容并排他发布"]
    S -->|准备失败| F["目标未创建，可修复后重试"]
    S -->|目标被其他创建者抢先占用| B["报告冲突，保留对方目录，本次不登记"]
    S -->|发布成功| R["向本机 instances.db 登记"]
    R -->|成功| OK["prepared，已登记"]
    R -->|失败| W["prepared，返回路径及登记失败原因"]
~~~

- **存在哪里。** 复用现有用户状态目录定位规则，依次采用 `WORKBOX_STATE_HOME`、`$XDG_STATE_HOME/workbox`、`~/.local/state/workbox`，文件名为 `instances.db`。每条记录保存实际绝对路径（唯一键）、创建时的配置名和创建时间。配置名用于展示，允许原配置之后改名或删除。SQLite 和 MySQL 团队配置共用这一本机清单。[状态目录入口](../../internal/workbox/settings.go)
- **何时拒绝。** 保留已有目标必须不存在、父目录可访问可写的检查。用解析符号链接后的父目录计算目标路径。路径已有登记，即使目录已删也要提示先 forget。自实际父目录逐级向上查找 `.workbox/repos.json`，发现标记就报告祖先实例路径；祖先已 forget 也适用。数据库不存在按空清单处理；已有库打不开、解析或查询失败时，报告原因并在发布前停止。
- **何时登记。** plan 只检查，不建库、不预留路径。create 独立复查，再由现有创建模块暂存和排他发布。仅成功发布后写入登记。并发创建同一路径时，保留排他发布和数据库路径唯一约束。发布前失败可在原因排除后重试；发布后写库失败，成功结果保留实际路径，同时返回可辨识的登记失败信息和原因，Agent 继续使用该目录。
- **如何找回。** list 逐条检查路径，显示路径、来源配置名、创建时间及下表状态。只检查目录类型，不读取实例内容或扫描磁盘。同一路径后来放入另一目录也显示 present。首版只登记功能上线后创建的实例。手动移动后，旧路径的记录保留，新位置不自动登记。
- **如何忘记。** forget --path 按唯一路径删除本机记录。用户可直接传入 list 输出的绝对路径，即使实例或父目录已被删除。优先精确匹配登记路径；没有精确匹配时，再解析仍有效的符号链接别名。这样即使旧路径后来成为指向另一实例的链接，用 list 给出的旧路径也只会忘记旧记录。目录及其内容由用户自行处理。第一版无需搬迁、删除目录或旧目录补录命令。

| list 状态 | 本次检查结果 |
| --- | --- |
| present | 路径是目录 |
| missing | 路径不存在 |
| not_directory | 路径存在，但不是目录 |
| unknown | 权限或其他错误使类型无法确定，随该条返回原因 |

### 模块接口与 Agent 用法

- 创建模块继续接收配置及目标路径，向 CLI 返回预览、发布前失败或已发布结果。plan 与 create 复用同一预检；创建模块统一处理发布和登记的先后关系。
- 本机登记模块封装路径查重、成功发布后的登记、列出记录并检查路径状态、按路径忘记记录。调用方无需管理 SQLite 连接和唯一约束。list 和 forget 的分派独立于团队配置库的初始化和连接。数据库本身不可读时报告操作失败，区别于某个目录的 unknown 状态。
- 同步 CLI 帮助、README 和全局 Workbox Skill。用户问“我之前有哪些需求目录”时用 list；问具体目录的检出情况时用 status；要求从清单移除时用 forget。Skill 应能解释目录已发布但登记失败，并继续在返回的路径工作。

## 验收

| 初始条件 | 操作 | 可观察结果 |
| --- | --- | --- |
| 本机无登记库 | list；对有效配置和新路径 plan | 空清单；预览成功。两次操作均不创建库或目标目录。 |
| 父目录可以通过符号链接访问 | 用别名 create，再 list | prepared；只见一条记录，路径为实际绝对路径，配置名、创建时间可见。 |
| 创建后切换配置库或共享 MySQL 离线 | list，再 forget 指定路径 | 清单仍可读；只移除指定记录，磁盘内容完好。导出或导入配置不携带实例历史。 |
| 目标已存在，或目标已删但登记仍在 | 分别 plan、create | 均拒绝；仅剩登记时提示先 forget。复制 list 的路径 forget 后，可对空闲路径重新 create。 |
| 已有实例被 forget，目录仍在 | 从父实例的实际路径及其符号链接下 plan、create 子实例 | 均拒绝，并返回有标记的父实例路径。 |
| plan 通过后另一进程占用目标，或两个 create 同时指向同一实际路径 | 发起 create | 不覆盖已有内容；并发时最多一个发布成功、最多一条登记。 |
| 登记库已损坏或不可读 | plan、create | 明确报告原因；不发布目录。修复后可用原命令重试。 |
| 必需文档下载失败；或发布后才发生登记写入失败 | 分别 create | 前者不发布、不登记，可用原路径重试。后者返回 prepared、路径和登记失败原因，Agent 继续使用该目录。 |
| 目录正常、已删除、被文件替换、不可访问 | list | 分别显示 present、missing、not_directory、unknown；最后一项说明原因。所有记录保留。 |
| 手动移动需求目录并删去旧父目录 | list，再用显示的原路径 forget | 旧路径显示 missing，新路径没有登记；旧记录可移除，新目录完好。 |
| A、B 均已登记，A 的旧路径后来成为指向 B 的符号链接 | 使用 list 中 A 的路径 forget | 只移除 A 的记录，B 的登记和两个路径均保留。 |
