# Workbox 产品愿景

一个需求常常涉及团队多个仓库的变更。Workbox 让成员为每个需求快速创建一个 Agent 工作环境。Agent 可以在其中阅读团队负责的多个仓库，分析这次需求会影响哪里、为什么需要改动。确定范围后，成员可以在同一环境里和 Agent 继续开发。

团队共同维护仓库清单、协作约定和工作方法。成员创建环境时可以直接复用这些上下文，从这次需求本身开始讨论。

## 用户价值

- **让团队经验可以复用。** 团队可以按场景维护多份配置，自行选择仓库、文档和 Skill。成员在协作中形成的新约定或改进的工作方法，可以更新到共享配置里，让后续接手需求的同事直接复用。
- **降低跨仓理解代码的门槛。** 成员可以从一个业务问题开始，即使还不知道实现在哪个仓库，也能让 Agent 在团队约定的范围内远程阅读代码，沿着调用关系解释现有行为，并给出可核对的代码位置。需要评估改动时，再据此判断影响范围。
- **让分析所得直接服务于开发。** 成员决定动手修改时，可以在同一需求目录里沿用已有的分析结论，也可以让同一 Agent 会话接着工作。Agent 只为需要改动的仓库准备开发用的 worktree，其他仓库仍可按需远程查阅。

## 代表性场景：一次接口变更

一位同事接到需求，要调整订单接口中一个字段的含义。他用团队维护的配置创建需求目录，请 Agent 查清：“这个字段由谁写入，哪些客户端依赖它现在的含义？”

Agent 在协议仓、服务仓和客户端仓中找到字段定义、写入逻辑和调用位置。两人据此确认，协议和服务实现需要修改，客户端只需验证兼容性。同事在同一会话里请 Agent 继续开发，为前两个仓库分别创建 worktree，验证时仍可远程查阅客户端代码。
