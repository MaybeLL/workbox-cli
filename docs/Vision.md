# Workbox 产品愿景

Workbox 让团队把共用的仓库信息、协作约定和工作方法配置一次，让每位成员都能为一个新需求创建 Agent 工作目录，从分析到开发持续使用。

## 一个需求从分析到开发

一个维护多个服务的团队收到接口变更需求。过去，每位同事都可能要向新会话重新介绍协议放在哪里、哪些服务使用它，以及团队希望怎样评估改动。团队成员可以按场景共同维护多份 Workbox 配置，自行决定每份配置带哪些文档和 Skill。接手需求的同事选好配置，就可以专注于说明这次要解决的问题。

在目标体验中，同事通过 CLI 创建需求目录。Agent 进入目录就能找到团队约定、仓库清单和配置选中的 Skill。即使协议仓、服务仓和客户端仓分属不同 GitLab Group，Agent 也能按照确认的分析范围和版本，远程搜索并阅读源码，给出哪些仓库需要改动、哪些只需验证，以及判断的依据。开始分析时，本机可以没有这些仓库的副本。

如果最终只需修改协议仓和服务仓，同事可以在同一目录、同一会话里继续开发。Agent 按需准备这两个仓库的本地代码，分别在各自的 Git worktree 中修改，直接沿用分析时找到的接口定义、调用位置和团队约定。

团队成员应当能只交代这次需求，就开始有依据的跨仓分析，并带着已有结论进入开发。产品演进中的取舍见[设计决策](Decisions.md)，当前版本的能力和用法见[使用说明](../README.md)。
